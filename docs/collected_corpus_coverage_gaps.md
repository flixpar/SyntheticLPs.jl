# Coverage gaps relative to the collected LP/MILP corpus

## Question and scope

This note compares the problem families generated by `SyntheticLPs.jl` with the
models actually exported into
`/mnt/internal/simplexrl-shared/milp-datasets/`. It answers a narrower question
than whether the package contains a broad optimization textbook survey: which
structural families that are materially represented in the collected corpus do
not yet have a faithful synthetic analogue?

The comparison uses the collected `catalog.tsv` generated on 2026-07-26. The
catalog contains 46,447 rows occupying about 277 GB. Exact normalized output
hashes reduce this to 44,285 distinct models; the manifest reports 2,162
duplicate files. Counts below use distinct output hashes so duplicated subsets
and the byte-identical MILPBench/ML4MILP HEM-MIK exports do not inflate a
family's importance.

Before the additions described below, `SyntheticLPs.jl` registered 33
categories and 70 variants. A category
name alone is not treated as coverage: variable domains, constraint structure,
and application coupling must resemble the collected formulation. This matters
for names such as `load_balancing`, where the two corpora use fundamentally
different models.

## Main findings

The largest missing or weakly represented families are:

| Family | Distinct collected models | Existing synthetic analogue | Assessment |
|---|---:|---|---|
| Generic hard binary/mixed IP | 10,100 | None | Missing. D-MIPLIB's family has 1,050 binaries, 33 continuous variables, and 195 rows per model, unlike the application-specific generators. |
| MIS, generalized independent set, and minimum vertex cover | 11,368 | None | Missing. These are sparse pure-binary graph models with symmetry, degeneracy, and characteristic weak relaxations. |
| Set cover and combinatorial-auction set packing | 6,910 | Airline crew exact-cover model only | Underrepresented. Set covering, packing, and partitioning require distinct senses and data regimes. |
| Discrete multicommodity min-cost flow | 4,000 | Continuous multicommodity flow; binary-link telecom design | Underrepresented. The collected BC/BI formulations contain binary capacity decisions and, for BI, general-integer flows. |
| Neural-network verification | 3,692 | None | Missing. ReLU big-M/disjunctive blocks produce a distinctive mix of many continuous activation variables and comparatively few binaries. |
| Optimal transmission switching | 2,900 | Continuous DC-OPF | Missing. OTS adds binary line status and topology-dependent flow limits to the DC network equations. |
| Discrete load balancing / placement | 900 | Continuous min-max traffic routing | Missing despite the shared name. Collected models have 1,000 binary and 60,000 continuous variables. |

These families contain 39,870 distinct models, about 90% of all distinct files
in the collected corpus. Some are related to existing categories, but none is a
clean formulation-level match except for portions of discrete network design.

### Graph packing and covering

The package has no graph-optimization category. D-MIPLIB contributes maximum
independent set, generalized independent set, and minimum vertex cover across
multiple difficulty regimes, while MILP-Evolve contributes another 1,000
maximum-independent-set models. These families should not be approximated with
knapsack or project selection: their edge-incidence matrices, graph density,
connected-component structure, and complement relationships are the relevant
features.

A synthetic graph family should share a reproducible graph sampler and expose
at least `independent_set`, `generalized_independent_set`, and `vertex_cover`
variants. Difficulty controls should alter graph model, density, degree
heterogeneity, and weight distributions rather than simply coefficient scale.

### Set systems and combinatorial auctions

The current airline-crew generator is a useful set-partitioning formulation,
but its columns are short flight pairings and its rows require exact coverage.
That does not cover generic set cover (`>= 1`) or combinatorial-auction winner
determination (`<= 1` item packing with bid values). Cutting stock also uses
pattern matrices, but its standard pattern-usage variables are continuous.

A shared set-system category should provide `set_cover`, `set_packing`,
`set_partitioning`, and `combinatorial_auction` variants with planted feasible
solutions, controllable row/column density, nonempty-row guarantees, and both
uniform and heavy-tailed set sizes.

### Generic distributional MILPs

Application generators do not substitute for D-MIPLIB's 10,100 generic hard-IP
instances or MIPLIB's heterogeneous structural coverage. A generic sparse MILP
generator is needed to control:

- binary, general-integer, and continuous variable proportions;
- packing, covering, equality, and ranged-row mixtures;
- finite, one-sided, fixed, and free bounds;
- sparse support distributions and block structure;
- integer and floating coefficient regimes, dynamic range, and near dependence;
- planted primal witnesses and explicit infeasibility certificates.

The first version should favor a transparent planted-solution construction over
claims of calibrated hardness. Difficulty calibration should be added only
after measuring solver behavior against held-out collected instances.

### Power-system topology decisions

The existing DC-OPF variant is intentionally continuous, and the existing unit
commitment generator permanently represents its commitment variables as
continuous `[0,1]` values. Neither therefore produces the binary topology
decisions found in 2,900 collected OTS models.

An `energy/optimal_transmission_switching` variant should extend the DC network
with a line-status binary, status-gated thermal bounds, and a valid big-M
relaxation of the DC flow equation for open lines. Feasible generation should
plant a connected active topology and dispatch witness; infeasible generation
should use a capacity or islanding certificate that remains invalid under the
big-M relaxation.

### Discrete multicommodity flow

The current multicommodity-flow generator creates only nonnegative continuous
flow variables. The collected MMCN family includes binary capacity-selection
models and general-integer flow variants. Telecom network design supplies some
binary-installation overlap, but it uses a different physical-link budget and
only continuous commodity routing.

The existing category should gain `binary_capacity` and `integer_flow`
variants. They should reuse common graph and commodity generation while making
the capacity modules, fixed charges, and variable domains explicit.

### Neural-network verification

Neural-network verification is structurally unlike the current statistical
regression generators. A faithful synthetic model needs layerwise affine
equations, pre- and post-activation variables, ReLU phase binaries for unstable
neurons, bound-derived big-M constants, an input box, and a linear output
property. Bounds must be generated first and propagated through the network;
arbitrary large constants would erase the formulation's defining structure.

## Smaller but meaningful gaps

- **Maritime inventory routing:** 118 models couple multi-period inventories,
  ship routing, loading, and delivery. Inventory and CVRP exist independently,
  but their coupling does not.
- **Seismic-resilient pipe-network planning:** 322 distinct models add damage
  scenarios, redundancy, and resilience decisions to fixed-charge flow design.
- **Fixed-charge transportation:** 31 distinct models require binary
  route-activation decisions; the current transportation variants are
  continuous.
- **Mixed-integer knapsack sets:** 90 distinct models (exported twice by two
  sources) contain 250--500 general integers, 5--20 continuous variables, and
  155--470 rows. The current bounded knapsack has a single integer block and one
  principal capacity row.
- **Container loading and multidimensional packing:** strIPlib contributes 83
  container-loading models plus two-dimensional bin-packing formulations.
- **Graph coloring, map labeling, and relaxed clique:** present in strIPlib but
  absent from the generator.
- **Integer cutting stock:** the collected strIPlib models are principally
  general-integer set-covering/set-partitioning formulations, whereas the
  standard synthetic variant uses continuous pattern counts.

These are second-wave additions. They broaden qualitative coverage but are much
smaller than the seven families in the main table.

## Existing strengths

Capacitated facility location is the clearest formulation-level match: both the
synthetic and D-MIPLIB models combine binary opening decisions with continuous
customer flows gated by facility capacity. The package also has useful coverage
for bin packing, lot sizing, scheduling, vehicle routing, cutting-stock
relaxations, and crew-pairing set partitioning. These need additional regimes or
integral variants rather than replacement.

The 471 distinct continuous Netlib/Meszaros models also reveal a cross-cutting
gap rather than a missing application: classic benchmark LPs contain varied
bound patterns, equality-heavy standard forms, free variables, coefficient
scales, degeneracy, and numerical pathologies. A later matrix-structure mode
should target those features without pretending to reconstruct unknown
application semantics.

## Dataset-level mismatches

Three package defaults prevent a nominally broad synthetic run from resembling
the collected corpus:

1. `generate_dataset` defaults to `relax_integer=true`. This is appropriate for
   an LP-relaxation campaign but silently removes the defining variable domains
   of most collected MILPs.
2. The default target-size distribution is truncated to 50--2,000 variables.
   Many collected families routinely contain 20,000--90,000 variables, with a
   much longer benchmark tail.
3. Random selection is uniform over registered variants. It therefore reflects
   registry organization, not the collected family distribution.

The package should preserve these backward-compatible defaults but add an
explicit, versioned `corpus_matched` preset. Its manifest must record family
weights, size distribution, integrality policy, and preset version. It should
not claim to reproduce solver difficulty until that claim is validated.

## Recommended implementation order

1. Add graph optimization variants: independent set, generalized independent
   set, and vertex cover.
2. Add set-system variants: cover, packing, partitioning, and combinatorial
   auction.
3. Add a transparent planted-solution generic sparse MILP generator.
4. Add optimal transmission switching under `energy`.
5. Add bound-aware ReLU neural-network verification.
6. Add binary-capacity and general-integer-flow multicommodity variants.
7. Add discrete placement and routed-workload load balancing.
8. Add a versioned corpus-matched sampling preset.
9. In a second wave, add fixed-charge transportation, mixed-integer knapsack
   sets, maritime inventory routing, container loading, and resilience network
   design.

Every new variant should satisfy the package contracts for deterministic seeds,
target variable counts, feasible/infeasible/unknown generation, integrality
relaxation, registry introspection, MPS export, and solver-backed feasibility
verification. Tests should exercise both relaxed and unrelaxed models and assert
the intended variable-domain mix, not merely that a JuMP model was constructed.

## Implemented response

The package now implements the recommended first and second waves as 23 new
variants across seven new and six existing categories. The registry contains
40 categories and 93 variants. Added formulations cover:

- sparse generic MILPs with mixed domains, varied column bounds, planted row
  systems, and LP-valid infeasibility certificates;
- independent set, generalized independent set, vertex cover, vertex coloring,
  map labeling, and quasi-clique graph models;
- set cover, set packing, set partitioning, and combinatorial-auction winner
  determination;
- binary-capacity and general-integer multicommodity flows, fixed-charge
  transportation, discrete placement/load balancing, and resilient network
  design;
- optimal transmission switching and bound-aware ReLU verification;
- mixed-integer knapsack sets, integer cutting-stock patterns, container
  loading/two-dimensional packing, and maritime inventory routing.

`corpus_matched_preset()` is versioned as `2026-07-26.v1`. Its weights cover
39,870 distinct collected instances (about 90% of the deduplicated catalog),
preserve integer domains, and use an operationally bounded heavy-tailed target
size distribution. The manifest records normalized weights, deterministic
family quotas, the resolved size distribution and generation policy, and
per-family attempt/filter/size-matching reports.

This closes the named formulation-family gaps, but not every distributional
gap. The generic MILP v1 supplies mixed row senses, positive packing/covering
coefficient regimes, several coefficient scales, and diverse column bounds; it
does not yet calibrate block structure, near-dependent rows, numerical
pathologies, or solver hardness against held-out MIPLIB/Netlib instances. The
preset likewise matches family prevalence rather than joint size, sparsity, or
runtime distributions. Those are measurement and calibration tasks, not claims
made by this implementation.
